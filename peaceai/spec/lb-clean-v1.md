# lb-clean v1: one-pass training-data cleaning (limit-breaker step 2)

Code: `peaceai/lib/lbclean.ts` (pure logic), `peaceai/bin/lb-clean.ts` (file I/O), config `peaceai/model/lb-clean.json`,
test `m150-lb-clean.test.ts`. Version string `peaceai-lb-clean:v1` (bump on any rule or output-field change).

It is not a second framework. The task-set exclusion is the M147 code in `nlpairs.ts`
(`parseExclusions`, `isExcludedRepo`, `mentionsExcluded`, `namesHashedRepo`) over the same files
(`nl-pairs-exclusions-public.txt`, `nl-pairs-exclusions-hidden-hashes.txt`). The tokenizer is the `eval_dedup.py`
one (`\w+|[^\w\s]`). Input and output use the format `nl-pairs.ts`, `ft_prepare.py` and `train.py` share:
`docs.jsonl` {doc,text} plus `manifest.jsonl` {doc,split,repo,path,function,...}. A pretrain manifest with `source`
in place of `repo` is accepted.

## Pipeline placement

    nl-pairs (or lm corpus) -> lb-clean -> ft_prepare -> eval_dedup (recheck) -> train (not on this box)

## Rules, in order

Per input doc, in doc-id order. Every drop is a fixed rule code, and the report holds counts only (no text, no
hidden name, no hash).

Whole doc:

| code | rule |
|---|---|
| taskset_repo | the doc's repo is a task-set repo (public by name, hidden only by sha256 of the lowercased owner/repo) |
| taskset_name | the text names a public task-set repo |
| taskset_hidden_name | the text contains an owner/repo token whose lowercased sha256 is in the hidden-hash list (never reversed or named) |
| junk_path | lockfiles (named ones, *.lock, *-lock.json/yaml), build-output dirs (dist, build, out, bundle, vendor, node_modules, coverage, generated, .next, ...), *.min/.bundle/.umd/.prod JS, source maps and snapshots; for a diff, any path in its `diff --git` or `+++ b/` headers |
| junk_generated_header | a generated-code marker (`@generated`, "do not edit", "auto-generated", "generated by") in a comment line in the first `headerLines` lines of the doc or of any diff section |
| junk_long_line | any line longer than `maxLineChars` |
| junk_minified | mean line length above `maxMeanLineChars` |
| junk_low_alnum | alphanumeric share of non-space chars below `minAlnumRatio` |
| junk_long_token | a base64 / hex style run longer than `maxTokenChars` (embedded data, not long regexes or prose) |

Then the doc is split. Text at or above `split.minChars` that parses as TypeScript/JavaScript without diagnostics is
cut only before a top-level unit (function, class, interface, enum, type alias, namespace, or a variable initialized
with a function or class). Units are packed greedily up to `maxChunkChars`. The split is lossless (the pieces join
back to the doc), and unparsable text such as a diff is never split.

Per piece:

| code | rule |
|---|---|
| taskset_near_dup | containment of the piece's `taskset.shingleTokens`-token shingles in the public task-repo trees at or above `maxContainment`. The refs file is built by `--build-refs` only from repos named in the public exclusion list; the hidden half is applied only through the hashed-name rules above. |
| exact_dup | same whitespace-normalized text as an earlier kept piece |
| near_dup | MinHash LSH candidates (FNV-32 shingles, fmix32 permutations with sha256-derived seeds, `bands` x rows), then exact shingle Jaccard at or above `jaccard` against an earlier kept piece. The first in doc-id order wins, across splits, so a heldout piece that copies a train piece is dropped. |

Kept pieces:

- `difficulty`: {score 0-100, level easy/medium/hard, chars, nesting, identifiers, tokens}, from the TypeScript
  scanner (bracket nesting outside strings and comments, distinct identifiers, token count) against the config caps.
- best-code repeats: a train piece whose doc's text sha256 is in `best.textSha256`, or whose {repo, pathPrefix}
  matches `best.paths`, is written `weight` times in total (`#repN`, `repeatOf`). At most `maxDocs` docs qualify.
- fill-in-the-middle: train pieces only, chosen at `fim.rate` by sha256(salt, text), with cut lines from the same
  hash. The format is PSM, `<prefix>pre<suffix>suf<middle>mid` (`#fim`, `fimOf`). A piece is skipped when it is short
  or already contains a sentinel.

Output function keys stay unique (`#pNofM`, `#repN`, `#fim`), so ft_prepare's (repo,path,function) collapse keeps
every piece. `src` is the input doc id, and `textSha256` is recorded per output doc.

## Fingerprint

`fingerprint.json` is written next to the output: {schema, fingerprint, parts, outManifestSha256}. The fingerprint
is sha256 over canonical sorted-key JSON of:

- schema
- cleanerVersion
- codeSha256 of lbclean.ts, lb-clean.ts, nlpairs.ts, lmcorpus.ts and tsresolve.ts
- typescriptVersion
- configSha256
- exclusionsSha256
- input {docsSha256, manifestSha256}
- refs {docsSha256, manifestSha256} or null

Without the cleaner version the fingerprint is refused.

## Fail-closed refusals

`exclusions_missing`, `exclusions_bad_line`, `exclusions_empty`, `exclusions_no_hidden_hashes`, `config_*`,
`input_missing`, `input_docs`, `input_manifest`, `input_docs_manifest_differ`, `refs_repo_not_public_by_name`,
`tasks_empty`, `refs_empty`, `typescript_not_found`, `usage`.

## Not done here

No training, no network, no paid compute. `eval_dedup.py` stays the held-out leak check after cleaning.
