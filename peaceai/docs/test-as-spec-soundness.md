# Test-as-spec and issue understanding

`verified_strict` means the candidate symbol and the fix symbol agreed on the recorded test's arguments and on at least one mutated input. The comparison includes the return value, the arguments after the call, and, when both sides throw, the error name and message. `NaN` matches `NaN`. `-0` does not match `0`, and `Infinity` does not match `-Infinity`.

It does not prove every input, and it does not prove the source text matches the fix. A result that is a function, a class instance, or another opaque value is `diff_unavailable`, not strict. A module that cannot be loaded on its own is `diff_unavailable`. A body that matches only the test's own arguments is `verified_test_only`.

The mutation set is finite and generic, capped at 50 inputs. A bug outside those inputs can still be called strict. The probe line carries a per-run nonce, so a hardcoded sentinel printed by the candidate is ignored. A candidate that reads the probe's spec file can still see that nonce. The solver tree does not contain the fix commit or the clone URL. The grader loads the fix in a separate tree after the solver returns.

Issue and commit wording is read inside Job A. `NOT_SUPPORTED`, `NO_FAMILY`, and `PARTIAL_PLAN` can now become a mapped plan and then candidates. Those candidates are still refused unless Job B's gate passes.

The sindresorhus/is guards copied into the tests exercise only this grader (`gradeBehavior`). They do not show that the solver generalizes.

`CANT_DO_YET_CAP` means test-as-spec tried its attempt budget and the repair proposer still had another proposal. That budget stays `min(MAX_ATTEMPTS, MAX_CANDIDATES)`, which is 20, for dev and held-out alike. A pre-registered plan for raising it is in `peaceai/docs/cant-do-yet-cap-plan.md`. The code is unchanged. A caller's `maxAttempts` cannot rise above that cap.

An Ava worker banner is an early exit unless the target test's own result is in the output. The failing line's trailing message is not removed. A test may be titled `target Test failed via \`t.fail()\`` and fail a different assertion, and that `✖` line is the same text as the target's own `t.fail()`. A detail title counts only when a `✖` or `✘ [fail]` line before the summary marks that same title, and the title line is inside the failure summary, between Ava's two rules, followed by `file:line`, by `Error: Test timeout exceeded`, or by `Error thrown in test:`. Output from a passing test is not that pair, so it cannot create a result. That line must equal the target. A longer title such as `target warm extra` is not `target warm`, and a title that only contains the target in the middle is not either. Another test's title does not count, including when that test failed and the worker then exited, or when `--fail-fast` skipped the target. A line `file › title` is a failure in that other file. It is not treated as the target's own line, even when the title text matches, so a real failure beside a crash in a different file stays `CANT_DO_YET_AVA_EARLY_EXIT`. The target's own timeout (`Test timeout exceeded`) or thrown error (`Error thrown in test`) counts when that marked detail line is the target, including when a worker banner is also present. A worker banner is `✖ <file> exited with a non-zero exit code` or `exited due to an error`, with a file path. A test whose title is that phrase is a normal failure. A banner with no result for the target, such as a compiler stop or an uncaught exception before any test, stays `CANT_DO_YET_AVA_EARLY_EXIT` and is not turned into an edit. `--tap` is not used: Ava 6.1.3's tap reporter throws when the worker calls `process.exit`.

An integer comparison scaffold may treat `a > n` and `a >= n+1` as one predicate, and `a < n` and `a <= n-1` as one predicate, only when every example argument is an integer and both bounds are safe integers. `n+1` and `n-1` are not used once they leave that range, including at `Number.MAX_SAFE_INTEGER`. Equality is not folded into a greater-than class. Strict credit is grader-guarded. Classic mutants keep the input budget. Boundary probes use a separate budget and sit on the adjacent representable floats of each literal bound, including `0` and negative bounds, not a fixed gap of `1e-6`. Dropping probes to fit that budget, as well as dropping mutants, stays `verified_test_only`. A numeric literal passed to `Object.is`, used as a `switch` case, as an element index, or passed to `.includes`, `.indexOf`, `.has`, `.get`, or `.startsWith` is probed, including one written in an array, `Set`, `Map`, or object in that same expression. A `const` in the same file, including one declared inside the function, is followed one step. A nearer declaration of the same name wins. A reassigned `let`, a destructured name, an imported name, a spread of a call, and `C.BAD` when `C` is not an object written in the file stay `verified_test_only`. A spread of an array literal is followed. `3 / 10` is the number 0.3. `~~`, `Math.floor`, `Math.trunc`, `| 0`, and `>> 0` around `a * n === m` contribute `m / n`, as does `a * n === m` itself. `/0[.]3/` contributes 0.3. `toLowerCase` and `trim` are probed with the other case and the padded text. `split` stays `verified_test_only`. A field probe on an empty object can show a disagreement, and it never earns `verified_strict`. A field probe is not applied to an object that already holds a number. `a.list.includes(1)` on a parameter that the function does not assign is probed; an assignment to that field is not trusted. `K.S.has` follows a class static initializer in the same file, and a later assignment to that static is not trusted. `3 / 10` is not a scale. `a / n === m` and `Math.floor(a / n) === m` contribute `m * n`. `Math.round` and `Math.ceil` are peeled like `Math.floor`. A read inside a nested function, and a receiver that is not a bare name, are not field probes. A string literal other than a `typeof` name is substituted at string inputs and, for `"Infinity"`, `"-Infinity"`, and `"NaN"`, at number inputs. A string that is only a number, such as `'0.3'` or `'1e-9'`, is also a numeric probe. `(a * n | 0) === m` contributes `m / n`. A regular expression contributes the numbers written in it. `Math.abs(a - 0.1) < 1e-12` contributes `0.1`. `.includes` of a non-literal stays `verified_test_only`. A comparison whose bound is not a literal, including `a === b` and `Object.is(a, b)`, stays `verified_test_only` even when the other side is a constant. `Date`, `Set`, and `Map` values are compared by their contents. A class instance is not strict. A throw is not the same as a return. The integer-collapse scaffold is not yet shown on an unmodified real-library test: `kevva/is-positive`'s own test is `CANT_DO_YET_SIGNATURE`, and its `1` / `0` / `-1` assertions are `CANT_DO_YET_NO_BODY`.
