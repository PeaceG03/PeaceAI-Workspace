# [host-failure-line] hostFailureLine: host failure line that keeps the error cause code

Target: PeaceG03/PeaceSTOCKS

Add a new module `src/host-failure-line.ts` exporting `hostFailureLine(message: string, causeCode: string): string`.

Behavior: build the one-line failure report the scheduler host prints. The line always starts with the marker MARKETS_SCHEDULER_HOST_FAILED, then a colon, then the message exactly as given. When a cause code is given, the line ends with a colon, the word cause, an equals sign and the cause code. When the cause code is empty, nothing is added after the message. The message and cause code are copied as they are, with no trimming or escaping.

Examples (message, causeCode gives line):
- "fetch failed", "ECONNRESET" gives "MARKETS_SCHEDULER_HOST_FAILED:fetch failed:cause=ECONNRESET"
- "fetch failed", "" gives "MARKETS_SCHEDULER_HOST_FAILED:fetch failed"
- "R2_GET_500", "" gives "MARKETS_SCHEDULER_HOST_FAILED:R2_GET_500"
- "", "UND_ERR_SOCKET" gives "MARKETS_SCHEDULER_HOST_FAILED::cause=UND_ERR_SOCKET"
- "", "" gives "MARKETS_SCHEDULER_HOST_FAILED:"
- "R2_PUT_500", "ETIMEDOUT" gives "MARKETS_SCHEDULER_HOST_FAILED:R2_PUT_500:cause=ETIMEDOUT"

Context (Builder pre-file, refile of #488, behavior only): Peace's task (source: peace). Every scheduled scan since 2026-10-14 ends with only MARKETS_SCHEDULER_HOST_FAILED:fetch failed because src/host.ts drops the error cause; this is the line the host will print once wired, with the cause code (never a URL) appended when there is one. This issue states only the wanted behavior and example cases; PeaceAI has to work out the implementation itself. Production safety: one new function in a new module plus one new test file under src/ only. Nothing imports it yet, so the running scanner, the scan and the ten-minute chain are unchanged. Wiring it in is a separate task (see batch-v4/scanner/DIAGNOSIS.md).
