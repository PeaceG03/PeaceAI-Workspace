# [r2-retry-delay] r2RetryDelayMs: bounded backoff for an R2 retry attempt

Target: PeaceG03/PeaceSTOCKS

Add a new module `src/r2-retry-delay.ts` exporting `r2RetryDelayMs(attempt: number, baseMs: number): number`.

Behavior: how many milliseconds to wait before retry number `attempt` (counting from 0), given a base wait of `baseMs`. Attempt 0 waits exactly the base. Each later attempt waits longer than the one before, following the pattern in the examples. The wait is never more than 30000 ms, whatever the attempt or base. A base of 0 always gives 0.

Examples (attempt, baseMs gives wait):
- 0, 1000 gives 1000
- 1, 1000 gives 4000
- 2, 1000 gives 9000
- 3, 1000 gives 16000
- 4, 1000 gives 25000
- 5, 1000 gives 30000
- 10, 1000 gives 30000
- 100, 1000 gives 30000
- 0, 500 gives 500
- 1, 500 gives 2000
- 2, 250 gives 2250
- 0, 0 gives 0
- 7, 0 gives 0
- 0, 40000 gives 30000

Context (Builder pre-file, refile of #487, behavior only): Peace's task (source: peace). The future R2 retry needs a wait that grows per attempt and never exceeds 30 seconds, so one retry cannot stall a scan. This issue states only the wanted behavior and example cases; PeaceAI has to work out the implementation itself. Production safety: one new function in a new module plus one new test file under src/ only. Nothing imports it yet, so the running scanner, the scan and the ten-minute chain are unchanged. Wiring it in is a separate task (see batch-v4/scanner/DIAGNOSIS.md).
