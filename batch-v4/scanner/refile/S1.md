# [r2-retry-status] isRetryableR2Status: which R2 reply statuses are worth retrying

Target: PeaceG03/PeaceSTOCKS

Add a new module `src/r2-retry-status.ts` exporting `isRetryableR2Status(status: number): boolean`.

Behavior: given the HTTP status code of a reply from R2, answer true when the request is worth retrying and false when it is not. Worth retrying: 429 (too many requests) and every server error status from 500 through 599. Not worth retrying: everything else, including success, redirect and other client error statuses, and anything above 599.

Examples:
- 429 gives true
- 500 gives true
- 502 gives true
- 503 gives true
- 504 gives true
- 550 gives true
- 599 gives true
- 428 gives false
- 430 gives false
- 499 gives false
- 465 gives false
- 600 gives false
- 700 gives false
- 200 gives false
- 204 gives false
- 100 gives false
- 301 gives false
- 400 gives false
- 403 gives false
- 404 gives false
- 0 gives false

Context (Builder pre-file, refile of #486, behavior only): Peace's task (source: peace). The ten-minute chain stopped on R2_PUT_500 (run 39451888891) and R2_GET_500 (run 39467160610) because R2ObjectClient.request never retries; this is the status check the future retry will use.
